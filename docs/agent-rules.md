# 開発進行における Copilot とオーナー（oggy8021）のルール

この文書は、プロジェクトにおける私（Copilot）とオーナーの間で合意した運用ルールをまとめます。小さな変更は随時更新し、重要な変更がある場合は履歴を残してください。

## 目的
- 作業フローを明確にし、無用な実装や承認漏れを防ぐ。

## 基本ルール
- 仕様書先行：機能追加や設計変更は、原則として仕様書（`docs/specs/*.md`）を作成・承認してから実装する。
- ドキュメント言語：仕様書・README・コメント・コミットメッセージは日本語を基本とする。
- コミット先：小規模なドキュメント更新や軽微な修正は `main` へ直接コミットして良い。大きな設計変更や実装はブランチを切り、PRでレビューする。
- 承認：実装はプロジェクトオーナーの承認が必要。オーナーが1人である場合も、承認レスポンスをファイルで残す（ファイル編集かチャットでの明示）。
- 相談事項：指針に明記されていない判断や重大な設計決定は必ずオーナーへ相談する。

## Copilot の役割と制約
- 私は仕様書の草案作成、解析、雛形生成、CI設定、テスト作成などを行う。実装の着手はオーナー承認後に行う。
- 誤解や不明点が発生した場合、必ず確認を求める。勝手な解釈で進めない。
- セキュリティや秘密情報（APIキー等）はリポジトリに書き込まない。

## コミュニケーションと記録
- 重要な決定は `docs/` 内の該当ファイルに記録し、コミットする。
- オーナーの返答は該当ファイルに「回答（オーナー名／YYYY.MM.DD）：...」で追記する。

## ルール更新方法
- ルールの変更は提案→オーナー承認で反映する。小さな補足は直接追記して構わないが、意味のある変更は承認を得る。
