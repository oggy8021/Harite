# CI戦略（草案）

目的

- 重要な組合せを効率よく検証しつつ、CIコストとフィードバック遅延を抑える。

原則

- 必須ジョブは短く、失敗時にデバッグに必要な最小限のアーティファクトを残す。
- 重い・非必須ジョブは分離してオンデマンド化またはスケジュール実行する。
- PR は小さく分割して段階的に CI を通す（fast feedback → extended verification）。

ジョブ分類（提案）

- 必須（PRごとに実行）
  - `lint`：スタイルと簡易静的解析（flake8/ruff）。
  - `unit-tests:py38`：メインのユニットテスト（最低1環境）。
  - `build-check`：sdist/wheel のビルド確認。
- マトリクス（縮約）
  - OS × Python の全組合せは重いので、必須は最小セットに絞る（例：Ubuntu+Windows+macOS の各1バージョン）。
  - 他はナイトリービルドまたは手動トリガーで実行。
- 拡張（必要に応じて、またはスケジュール）
  - `integration`：実環境に近い統合テスト（オンデマンド）。
  - `coverage`：カバレッジ集計とレポート（夜間実行で十分）。
    - 補足: `coverage` は毎回実行せず、手動トリガー（`workflow_dispatch`）で必要な都度実行します。

キャッシュとアーティファクト

- 仮想環境・依存キャッシュ（pip cache、Poetry cache）を有効にする。
- 失敗時に必要なログ（pytest-xml、stderr/out）とビルドアーティファクトを短期間保持（例: 7日）。

プルリクエストワークフロー

1. PR 作成時: `lint` + 最低限の `unit-tests` を実行（早期フィードバック）。
2. 承認前: 必須ジョブがグリーンならレビュー→マージ候補。
3. マージ前/マージ時: `build-check` を通過させる（保険）。
4. マージ後: ナイトリーバッチで完全マトリクス・拡張テストを実行。

デバッグ支援

- 重要な失敗には`run: pytest -q --maxfail=1 --showlocals`相当の詳細ログを残す。
- 再現困難なケース向けに、アーティファクトに実行時の環境変数ダンプと簡易環境情報を含める。

コスト最適化の提案

- PRごとのジョブは短くし、重いジョブはスケジュールまたは手動トリガーにする。
- キャッシュを積極利用し、依存解決の時間を短縮する。

導入のための次のアクション（短期）

1. この草案に同意 → `docs/ci-strategy.md` をレビュー・微修正。
2. 必須ジョブの GitHub Actions ワークフローを作成（小さく始める）。
3. ナイトリービルドで拡張マトリクスを実行するジョブを追加。
