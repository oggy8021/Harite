## 検出ギャップと対応

### テスト追加（本 PR）

- `tests/gui/test_qt_widget_helpers.py` — `refresh_slideshow_registry_combos` が owner の profile / source id を combo 選択へ復元することを検証（gui-spec §6.3 startup 同期）。

### 意図的に残す項目

| 項目 | 理由 |
|------|------|
| **GTK registry widget parity** | gui-spec は parity 対象だが、P-01/P-02 と同型で **Qt-first**。GTK backend に combo / manage row 未配置。 |
| **Manage dialog 自動 UI テスト** | modal + QFileDialog 依存。core CRUD と handler テストで契約はカバー。 |
| **CLI `harite source`** | オーナー決定で C-02 外（打ち止め）。 |
| **ordered list profile** | planning / spec で非採用。 |
| **settings 無効 id の自動クリア** | source-spec §7.3 — delete 可、GUI 復元時クリアは **次回操作時** でよい（現状 combo は `— none —` にフォールバック）。 |

## 結論

3層比較で **core / Qt GUI の主要要件は一致**。検出したテストギャップ 1 件（combo refresh）を本 PR で追加。GTK parity と dialog E2E は follow-up として feature-overview / gui-spec の既知スコープ外に明記。
