# 開発チェックリストと運用ルール

以下は `.github/.copilot-instructions.md` とオーナー回答に沿った、当プロジェクトの開発チェックリストおよび運用ルールです。

## 基本方針

- 言語: Python 3.12+
- 仕様書先行（Specification First）: 仕様書を作成・オーナー承認後に実装する。
- 日本語ドキュメント: 仕様書・README・コミットメッセージは日本語で作成する。
- オーナー承認: 実装は `プロジェクトオーナー` の承認が必要。

## リポジトリ構成（初期案）

- `pyproject.toml`（Poetry or hatch検討）
- `src/harite/` パッケージ
- `tests/`（pytest）
- `docs/`（仕様書・設計・オーナー確認ログ）

## コーディング規約

- 型ヒントを付与する（関数・公開API）。
- 非同期処理は必要に応じて採用する。
- 依存は最小限に。新規依存は提案時に理由を明記する。
- フォーマッタ: `ruff` + `black`（提案）。

## ブランチとレビュー

- ブランチ命名: `feature/<短い説明>`、`fix/<説明>`、`chore/<説明>` など。
- 1機能 = 1PR。PR作成前に仕様書リンクを貼る。
- レビューはオーナー承認が原則。Automerge禁止。

## 仕様・設計フロー

1.機能要求を記載した仕様書（Markdown）を `docs/specs/` に作成する。テンプレートを利用。
2.オーナー承認（ファイル内コメントまたは承認レスポンス）を得る。
3.実装用タスクを作成し、PRに仕様リンクを貼る。

## テスト方針

- 単体テスト: `pytest`。
- コア計算ロジックは過去のテストを参照して互換性を検証する。
- CIは最小構成で開始（ユニットテストのみ）。GUIやXvfbは後段。
- カバレッジ目標: 制限しないが重要箇所は重点的に。

## CI / CD

- GitHub Actions で最小構成を用意: Lint → Unit tests。
- Xfce GUIテスト等は後段で追加。

## リリースと配布

- PyPI配布はXfce版完成後に検討。パッケージ名: `harite`。

## コミット・PRテンプレート

- コミット: 短い要約（日本語）+ 詳細。参照仕様書のリンクを含める。
- PRテンプレートに「仕様書リンク」「変更概要」「テスト手順」を必須項目とする。

## 承認・連絡フロー

- 仕様書提出後、オーナーはVSCodeチャットかファイル編集で承認を返信する。
- 重要な設計変更はファイルでの合意を優先する。
- 目安応答時間: VSCode起動中は随時対応可（急ぎでないこと）。

## 決定事項（2026-04-10）

- 同一性証明は、内部実装の一致ではなく、利用者から見える仕様同一性（インターフェース・振る舞い・目的）を対象とする。
- 同一性証明の必須ドキュメントは `Explain` と仕様書を基本セットとし、実装後はテスト結果で検証する。
- adapter禁止方針は旧実装互換の中間層を対象とし、UIバックエンド抽象化は安全性と依存分離のため許容する。
- 旧CLI互換は優先復元対象の上位5オプションを先に固定し、残項目は段階的に復元する。
- Linux Mint (Xfce) 実機検証の最小環境は、オーナーの現行使用環境に合わせて固定する。
- GUI Phase 3 完了判定の最小操作セットは `docs/manual-validation-gate.md` に固定し、受け入れ基準として運用する。

## 指針の不明点・要相談事項（解消状況）

- 旧CLI互換の上位5項目は `docs/specs/cli-top5-priority-options.md` で確定済み。
- 互換性と現代化の優先順位は「利用者から見える仕様同一性を優先」として運用確定済み。
- CLIフレームワークは現行実装（`src/harite/cli.py`）で Typer を採用済み。
- 現時点の残件は「未決事項」ではなく、次フェーズ候補（watch/常駐系）の仕様化のみ。

## オーナー相談用の質問リスト（次フェーズ候補）

- `harite watch` の最小スコープをどこまで含めるか（ランダム/順次、間隔指定、終了条件）。
- watch 機能で `apply --do-it` を初期から許可するか、まず dry-run 限定で入るか。
- 常駐機能（daemon/applet）は watch 実装後に別仕様として扱う方針でよいか。

- 完了条件: オーナー承認コメントを取得し、CLIテスト観点を `tests/cli/` 追加計画としてリンク済み。
