# Docs Consolidation Plan

目的
- `docs/` フォルダ内の重複・表記ゆれ・古い情報を段階的に整理し、レビューしやすい小さな PR に分割して適用する。

アプローチ（段階）
1. スキャン: 重複や表記ゆれ候補をリストアップ（ファイルと短い説明）。
2. 優先付け: 重要度と影響範囲でタスクを並べ替え（typo → 用語統一 → 構造変更）。
3. 実装: `feature/docs-consolidate-001` など `feature/` プレフィックスで小さな PR を順次作成。
4. レビュー & マージ: CI 通過後に squash マージ、マージ後の最終確認を実施。

短期タスク例（最初のラウンド）
- `feature/docs-consolidate-001`: 小さな typo と表記ゆれ修正（複数ファイル、1 PR）
- `feature/docs-consolidate-002`: ドキュメントタイトルと目次の統一

運用ルール
- 作業は常に `main` から `feature/` ブランチで行う。
- バックアップは `save/*` を使用し、PRチェックはスキップされる。
- 1 PR = 1 論点（ただし小さな typo 群はまとめて可）。

初回アクション
- このブランチ `feature/docs-consolidate-001` を作り、上記の短期タスク（typo 修正）を開始します。
