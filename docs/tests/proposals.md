# 提案集および次の作業案

以下は現在の状況（追加したテスト・スクリプト・運用ポリシー）を踏まえた短期〜中期の提案です。優先度をつけて順に実施することを推奨します。

## 優先（短期）

- CI 安定化: 重いテストは `slow` マーカを付与し別ジョブで実行。デフォルトジョブは高速スモークとユニットに限定する。
- 追加テスト（必須）: `harite.workspace` のディスプレイ検出パーサを文字列ベースで単体テストする。OS 依存ロジックはモック化して分離。
- 例外/エラーハンドリング: 破損画像・読み取り権限エラー時の挙動をテストしてハンドリングを明確化する。

## 中期（中〜長期）

- カバレッジ目標: 機能単位で 70%-80% を目標に設定。グローバルな閾値はプロジェクト状況に合わせて決定。
- 性能テスト: メモリと時間のボトルネック検出のため、CI に軽量パフォーマンスジョブを追加。
- ドキュメント自動化: `apply_docs_replacements.py` の差分レポートを PR テンプレートに自動添付するワークフローを検討。

## 改善提案（具体的実装案）

1. `tests/conftest.py` を整備して共通フィクスチャ（小画像、tmp output dir）を提供する。
2. `requirements-dev.txt` を作成して CI とローカル dev 環境で同一の依存を保証する。
3. `pytest.ini` に `markers`（slow 等）とテスト並列実行オプションを追加する。
4. pre-commit フックで `python -m pytest -q` の簡易スモークを実行する（ローカル品質向上）。

## 推奨次アクション（短いタスク順）

1. `tests/conftest.py` を追加（共通 make_image 等）。
2. `requirements-dev.txt` を作る（pytest、Pillow 等）。
3. `pytest.ini` を追加しマーカ定義（slow）を追加。
4. `harite.workspace` のパーサに対する単体テストを 3 件追加。
5. CI ワークフローに `slow` ジョブを追加（必須でない）。
