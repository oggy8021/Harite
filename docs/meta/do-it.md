**`--do-it` (実行モード) の取り扱い**

- **目的**: `harite` は副作用を含む操作（壁紙の適用など）を安全に扱うため、デフォルトで「ドライラン（安全モード）」を採用します。`--do-it` はその抑止を明示し、実際に副作用を発生させるための明確な意思表示です。

- **基本ルール**:
  - デフォルト: すべての適用コマンドは `dry-run`（副作用なし）で動作します。
  - 明示的実行: 実際に壁紙を適用するにはコマンドに `--do-it` を付与してください。
  - ログ: `--do-it` を付けない実行は操作内容を詳細にログに残しますが、外部コマンドは呼び出しません。

- **例**:

  - ドライラン（安全）:

    ```sh
    harite apply path/to/wallpaper.png
    ```

  - 実行（副作用あり）:

    ```sh
    harite apply path/to/wallpaper.png --do-it
    ```

- **プラグイン実装の期待動作**:
  - プラグインは `dry_run=True`（デフォルト）時に外部コマンドやシステム設定を変更してはいけません。
  - `dry_run=False`（`--do-it` 相当）の場合にのみ、外部コマンド（`xfconf-query`/`gsettings`/`feh` 等）を呼び出します。
  - テストでは `dry_run=False` の挙動をモックして検証します（CI 安全性のため）。

- **安全上の注意**:
  - `--do-it` は取り消し不能な操作を行う可能性があります。自動化スクリプトや cron で利用する場合は、想定どおりの引数・ファイルが渡されているか必ず検証してください。
  - 複数モニタ向けのマッピング（辞書指定）を使用する場合、キーとモニタ名の対応が誤っていると意図しない画面が変更される恐れがあります。

- **運用提案**:
  - 手動実行では常にまずドライランでログを確認し、期待通りのコマンド候補が出力されることを確認してから `--do-it` を実行してください。
  - CI や自動化ジョブでは `--do-it` を使わない運用を推奨します（テストやデプロイ時に自動的に実行されないようにするため）。
