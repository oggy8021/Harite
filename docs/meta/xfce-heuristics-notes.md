## XFCE Heuristics — 調査ノート

ブランチ: feature/xfce-heuristics-001
作成日: 2026-03-15

目的

- XFCE 環境における表示・検出の誤動作やコマンド失敗の原因を特定し、再現手順とテストを整備する。

範囲

- マルチモニタ、ディスプレイ識別、ウィンドウマネージャ差異、環境変数やコマンドの失敗ケース。

既知の問題（要約）

- 一部環境でディスプレイ判定が失敗し、`optimize_wallpapers` 等が期待通り動作しない。
- XFCE セッションでコマンドがタイムアウトするケースが報告されている。

実行環境候補

- Ubuntu + XFCE (実機/VM)
- Debian + XFCE
- XFCE on Wayland / X11 (可能な範囲で)

データ収集項目

- 実行ログ（--verbose 出力）
- 環境変数 (`DISPLAY`、`XDG_SESSION_TYPE`、`XAUTHORITY` 等)
- xrandr / xfce4の出力とコマンドの終了コード
- Python のトレースバック（例外発生時）

初動調査手順

1. 再現手順を最小化して記録: どのコマンドを実行すると失敗するか（スクリーンショット/ログ付き）。
2. 該当環境で `python -m harite` を `--verbose` で実行し、フルログを得る。
3. `xrandr` や `xfce4-display-settings` の出力を保存。
4. 失敗時の環境変数を `env` で収集。

仮説（例）

- 環境変数やセッションタイプに依存する分岐があり、XFCE の一部セッションで想定されるパスにアクセスできない。
- マルチモニタのID付与ルールが X11 と Wayland で異なり、パーサが落ちる。

初期タスク（次の 3 日）

- (A) 再現ログを 3 件収集してこのノートに貼る。
- (B) リポジトリ内で該当処理（表示判定周り）の関数を特定してコメントを追加。
- (C) 必要なら単体テストを一つ追加して失敗ケースを固定化する（`tests/` に parametrize で追加）。

期待成果

- 再現手順の文書化
- 最小限の回帰テスト
- 改善案（コード変更 or 環境チェック）の候補
