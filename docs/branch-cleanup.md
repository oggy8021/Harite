# ブランチクリーンアップ運用

## 目的

- マージ済みブランチの残留を減らし、ブランチ一覧の可読性を保つ。
- 誤削除を避けるため、削除対象と除外対象を明確化する。

## 基本ルール

- `main` へマージ済みで、不要になった作業ブランチは削除する。
- 原則として PR マージ時に `--delete-branch` を使う。
- 残存ブランチは週次ジョブで再確認し、条件に合うものだけ削除する。

## 除外ルール

- 次のブランチは削除対象外とする。
  - `main`
  - `master`
  - `save/*`
  - `discuss/*`

## 自動クリーンアップ

- ワークフロー: `.github/workflows/branch-cleanup.yml`
- トリガー:
  - 毎週日曜 03:15 UTC（JST 12:15）
  - 手動実行（`workflow_dispatch`）
- 安全策:
  - オープンPRの head ブランチは削除しない
  - マージ後 2 日未満のブランチは削除しない
  - 1回の実行で最大 20 ブランチまで
  - `dry_run` で削除なし確認が可能

## 手動運用の例

- 先にドライランを実行し、削除対象を確認してから実削除を実行する。
- 自動削除後は PR 一覧・ブランチ一覧を軽く確認する。
