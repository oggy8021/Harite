目的

短い合意手順

重要な運用ルール（要点）
- PR は原則 `feature/|fix/|docs/|chore/` プレフィックスで作成してください。
- 直接 `main` へ push せず、PR を介して CI が通ったら squash マージしてください。
- `save/*` はバックアップ扱いで PR チェックをスキップします（既設定）。

- Web Editor 等でリモート上から直接コンフリクト解消を行わないこと。
   - コンフリクトはローカルで解消し、チャット内で合意を得てからコミット→push→PR の順で反映する運用とします。
