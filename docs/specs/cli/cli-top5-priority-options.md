# 旧CLI互換 上位4オプション確定仕様

最終更新: 2026-04-11

## 目的

- 旧CLI互換の復元対象を上位4オプションに固定し、段階的な互換復元を可能にする。
- 小PR単位で実装と検証を進めるため、優先順と受け入れ基準を明文化する。

## 背景

- 旧実装はオプション数が多く、同時復元は検証コストが高い。
- 現行CLIは主要機能を提供しているが、移行時に重要な互換ポイントを先に固定する必要がある。
- 本仕様は「最初に復元する4項目」を固定し、残項目は後続で段階復元する方針を取る。

## 対象範囲

- 対象コマンド: `harite optimize`
- 対象オプション: `--config`、`--two-screen`、`--l-display`、`--r-display`、`--margins`
- 実装参照: `src/harite/cli.py`、`src/harite/core.py`
- 参照仕様: `docs/specs/cli-compatibility.md`、`docs/specs/optimize-input-and-two-screen.md`

## 優先復元対象（上位4）

- `--config`
  意図: 旧設定運用からの移行コストを下げる。
  仕様: 明示CLI値が設定値を常に上書きする。

- `--two-screen`
  意図: 旧運用で利用価値の高い2画面配置の中核を復元する。
  仕様: 2画面モードの起動条件と挙動を固定する。

- `--l-display` / `--r-display`
  意図: 左右ディスプレイ寸法の明示指定を互換維持する。
  仕様: `--two-screen` 併用時の優先ルールを固定する。

- `--margins`
  意図: 見た目再現で影響が大きい余白制御を復元する。
  仕様: 4値入力（left,right,top,bottom）を検証し、配置計算へ反映する。

注記:

- 上位4は「4項目」の管理単位として扱い、`--l-display` と `--r-display` は同一項目として扱う。

## 詳細仕様

### `--config` 優先順位

- 優先順は `CLI引数 > --config の値 > 既定値`。
- `--resolution`、`--input` など必須相当項目は、上記優先順で最終値が解決できない場合にエラーとする。

### `--two-screen` と左右ディスプレイ指定

- `--two-screen` が有効で `--l-display` と `--r-display` が揃う場合、左右幅を明示指定として扱う。
- 入力は先頭2件を使用し、先頭を左、2件目を右へ割り当てる。
- 3件目以降は本フェーズでは非対象（仕様変更時は別PRで明示する）。

### `--margins`

- 受理形式は `left,right,top,bottom` の整数4要素。
- 負値は不正入力として扱う。
- 余白は描画有効領域の制約として適用する。

## 受け入れ基準

- 各対象項目に、正常系1件以上と異常系1件以上のテストが存在する。
- `--two-screen` + `--l-display` + `--r-display` + `--margins` の組み合わせケースで、配置結果が仕様どおりである。
- `--config` 指定時、CLI明示値が設定値を上書きすることをテストで確認する。
- ヘルプ文言と実装挙動に矛盾がない。

## 達成状況（2026-04-11）

- [x] `--config` の優先順位（CLI > config > default）を CLI テストで固定。
- [x] `--two-screen` の config 連携を実装し、優先順位を CLI テストで固定。
- [x] `--no-two-screen` を導入し、config true を CLI で false 上書き可能化。
- [x] `--two-screen` + `--l-display` + `--r-display` + `--margins` の組み合わせケースを CLI テストで固定。

## テスト観点

- 単体:
  - 入力値検証（解像度、margins、必須項目解決）。
  - 優先順位（CLI値 vs 設定値）。
- 統合:
  - 2画面配置の結果検証（左右割り当て、余白反映）。
- 回帰:
  - 既存の optimize/apply 基本動作が崩れていない。

## 小PR実装順

1. `--config` の優先順位仕様を固定し、テストを追加する。
2. `--two-screen` + `--l-display/--r-display` の優先ルールをテストで固定する。
3. `--margins` の境界値テストを拡充する。
4. 仕様書と `--help` 文言の整合を最終確認する。

## 非対象（この仕様では扱わない）

- watch/daemon/applet 相当の常駐系機能。
- `align` / `valign` など他の細オプションの優先度確定。
- `.walloptrc` 自動探索読込の有無（`--config` 明示指定以外）。

## 方針決定（2026-04-11）

- `.walloptrc` の自動探索読込は現時点で採用しない。
- 設定ファイル利用は `--config` 明示指定を継続する。
- 自動探索を導入する場合は、別仕様（互換性・安全性・探索優先順位）として分離して扱う。

## 方針決定（2026-04-23, 入力順）

- `fixed` / `no-fixed` は廃止した。
- 2画面時の左右順は常に入力順とする。
- 仕様変更時は、`--help` 文言と回帰テストを同一PRで更新する。

## オープン事項

- なし（本仕様の対象範囲は方針決定済み）。
