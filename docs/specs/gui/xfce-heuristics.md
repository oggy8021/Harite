# XFCE Heuristics — 仕様（ドラフト）

目的

- XFCE 環境での壁紙設定候補（index / resolution / position）を安定して検出・適用するためのアルゴリズム仕様。

範囲

- 入力: `xfconf-query --list` などから得られる設定キー一覧/値文字列、検出されるディスプレイ情報（`detect_displays()` が返す幅/高さ/位置）。
- 出力: 候補リスト（identifier, index?, resolution?, position?）, スコア、選択ルール。

設計目標

- 環境依存の表記ゆれに頑健であること（normalize/aliases）。
- 複数候補がある場合は位置ヒューリスティクスで最適候補を選択すること。
- テストで再現可能／モック可能であること（`xfconf-query` を直接呼ばずに単体検証できる）。

主要処理フロー

1. 正規化 (`_normalize_identifier`)：小文字化、記号削除、common aliases（e.g. `wallpaper`/`backdrop`）マップ適用。
2. トークン化 / 変種生成 (`_name_variants`)：単語分割、複合トークン抽出。
3. 候補抽出：キー文字列から index/resolution/position 情報を正規表現で抽出。
4. スコアリング：
   - 名前一致度（トークンの包含/順序）
   - 解像度一致度（exact > close）
   - 位置一致度（マンハッタン距離に基づく閾値 `POS_MATCH_THRESHOLD`）
   - 候補の優先度（明示的 index を持つものを高めに採点）
5. 選択ロジック：スコア上位を採用。スコア差が小さい場合は position を決め手にする（例: 同一解像度で別ディスプレイがある場合）。
6. フォールバック：明確な候補がない場合は環境に最も近い名前の最小差候補を選ぶ。

閾値・パラメータ

- `POS_MATCH_THRESHOLD`：位置一致を許容する距離（デフォルト値は既存実装に準拠）。
- 解像度差許容：ピクセル差の割合ベース (例: 5%)。

テスト要件

- 正規化テスト：alias・記号混在の入力が期待される正規形に変換されること。
- 抽出テスト：典型的な `xfconf-query` ラインから index/resolution/position が抽出されること。
- スコアリング統合テスト：複数候補が与えられたときに期待候補を選ぶこと（モック `detect_displays()` を利用）。
- 境界ケース：ローカル表記の極端な揺らぎ、同一スコアのタイブレーク、単一ディスプレイ／複数ディスプレイ混在。

受け入れ基準

- 既存のユニットテスト（`tests/test_plugins_xfconf*`）と新しい再現テストがすべてパスすること。
- 実環境で `No known wallpaper setter found on PATH` のような誤検出が減ること（定性的評価）。

未解決 / 議論点

- 複数解像度のモニタでの「最適」解像度定義（拡張：ユーザ設定の優先順位を導入するか）。
- 位置一致の閾値は固定か、解像度に依存させるか。
