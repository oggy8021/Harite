## 事前相談が必要な項目

### 1. `Prefs` `Help` `About` の見せ方

- 確認したい点:
  - 文字メニューとして並べるだけでよいか。
  - メニューバー風に見せるか、単純なテキストリンク風に見せるか。
- 手戻り理由:
  - 上部帯の構図と余白設計に影響する。
- 推薦実装:
  - 現在の標準的なデスクトップ UI と今回の owner 意図を両立させるなら、独立ボタン列ではなく、タイトル直下の軽いメニューバーとして置くのがよい。
  - 見た目は重い native menu bar 再現より、横並びテキスト + 十分な余白 + hover 反応程度に留める方が、GTK 実装でも破綻しにくい。

### 2. `Save As` の視認位置

- 確認したい点:
  - flow 行の右端固定でよいか。
  - title/menu 行ではなく flow 行へ置く理解でよいか。
- 手戻り理由:
  - 上部帯の高さと右下主操作領域の境界に影響する。
- 推薦実装:
  - `Save As` は title/menu 行ではなく、`Flow: Compose -> Optimize -> Apply` と同じ行の右端へ置くのが最も読みやすい。
  - これは「保存先の補助導線」であり、「アプリ全体メニュー」ではないため、flow 行に属させる方が意味がぶれない。

### 3. 中央 2 列目の再現粒度

- 確認したい点:
  - `中央2列目イメージ` に対して、どこまで厳密に寄せるか。
  - GTK/current 実装都合で完全一致できない場合の許容範囲。
- 手戻り理由:
  - ここが曖昧だと Phase6 の再レビューで再度差し戻しになりやすい。
- 推薦実装:
  - 推薦は「座標の完全一致」ではなく、「意味配置の厳密一致」である。
  - つまり、上/下/左/右のトグル位置関係、左右ディスプレイイメージ、中央列の軸は厳密に守り、余白や widget サイズだけを GTK 都合で調整する読みがよい。
  - 再現が難しい場合も、意味配置を崩して左寄せへ逃がすのではなく、中央構図を保った代替レイアウトを優先する。

### 4. watch タブの切り替え単位

- 確認したい点:
  - 切り替え対象を「中央 2 列目のみ」と読むことで確定してよいか。
  - main 側に残す watch 要約は `running / stopped` のみで十分か。
- 手戻り理由:
  - タブ構造の骨格を先に誤ると、後段の結線をやり直すことになる。
- 推薦実装:
  - 切り替え対象は「中央 2 列目のみ」で固定するのがよい。
  - main 側に残す watch 要約は、レイアウト先行段階では `running / stopped` のみで十分であり、詳細状態や source は watch 側へ寄せる方が main の構図を守りやすい。

### 5. 右下主操作領域の見た目

- 確認したい点:
  - `Optimize` / `Apply` を単純に近接配置でよいか。
  - 視覚的な囲みや区切りが必要か。
- 手戻り理由:
  - レイアウト先行レビューの中心観点になる。
- 推薦実装:
  - `Optimize` / `Apply` は単純に横または縦で近接配置しつつ、軽いグルーピングだけを付けるのがよい。
  - 強い枠線やパネル化を先に入れると中央 2 列目より目立ちやすいため、余白・整列・小見出し程度で主操作領域を読ませる設計を推薦する。

### 6. Status と Debug の境界

- 確認したい点:
  - `Status` に残すべき情報の最小集合。
  - debug 表示を完全に仮領域として見せるか、軽い区切りを付けるか。
- 手戻り理由:
  - 最下部帯の高さと中央 UI の縦バランスに影響する。
- 推薦実装:
  - `Status` は短い状態要約だけに留め、debug は最下部の別帯へ分離するのがよい。
  - debug は完全に同化させず、細い境界線か背景差だけを付けた控えめな開発用帯として見せる方が、後で非表示化しやすい。

### 7. `Color` の扱い

- 確認したい点:
  - 今回は完全に非表示扱いでよいか。
  - 単に未配置のまま残すのか、UI から見えない形で外すのか。
- 手戻り理由:
  - レイアウトに見える要素かどうかでレビュー印象が変わる。
- 推薦実装:
  - `Color` 機能そのものは今回見せず、主レイアウト決定から外す方がよい。
  - ただし後置き予定のボタン配置だけは開いたエリアに吸収できる余地を残し、今は非表示のまま slot だけ考慮する設計を推薦する。

## 実装前に確認が済めば着手しやすいこと

- 上部帯の高さ
- flow 行の最終文言
- 中央 2 列目の再現優先度
- watch tab の枠だけ先に入れるか、ダミー表示にするか
- status/debug の境界線の有無

- 中央列不要ラベルの削除
- debug 情報を status より下へ落とす準備
- 左寄せ仮配置をやめ、中央 2 列目として再構成する方向づけ
