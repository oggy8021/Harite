# Docs Consolidation — 置換プレビュー（差分案）

対象: `docs/` 配下の Markdown ファイル（コードブロックは除外して検出）

処理方針:

- ASCII のカンマ `,` → 全角読点 `、`
- ASCII のピリオド `.` → 全角句点 `。`
- コードブロック（```...```）とインラインコード（`...`）は変更対象外

検出サンプル（ファイル: 抜粋）:

- `docs/do-it.md`:
  - `harite apply path/to/wallpaper.png` の説明文周辺はコードブロック内のため除外。
  - 説明文: "ログ: `--do-it` を付けない実行は操作内容を詳細にログに残しますが、外部コマンドは呼び出しません。"（置換不要の例）

- `docs/dev-environment.md`:
  - `python -m pip install -e .`（コードブロック内、除外）
  - `git add .`（説明内のコマンド例; ライン末尾の ASCII ピリオドは除外されるべき）

- `docs/docs-consolidation-scan.md`:
  - "主要な観点\n 用語統一: `main` の表記に統一、`docs` 表記の一貫化" → 提案: `用語統一：` のようにコロンも全角化検討

- `docs/docs-consolidation-actions.md`:
  - 箇条書きの区切りや説明文で ASCII 句読点を検出。例: "注意（作業ルール）:" → `注意（作業ルール）：`

- `docs/docs-consolidation-progress.md`:
  - "これまでの主な処理\n- `typo` → `タイプミス` など日本語表記の統一" → 文脈により句点追加の検討

提案される次手順:
1.プレビューを確認してよければ、上記ルールでワーキングツリーへ自動置換を実行します（コードブロック除外）。
2.置換後、差分を表示してあなたに確認を求めます（必要なら個別ファイルごとにロールバック可能）。

注記: 本プレビューは抽出サンプルです。実際の置換はファイル全体を解析して適用します。
