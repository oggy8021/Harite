## 固定要求

### 1. タイトル

- アプリケーションタイトルは `Harite` とする。
- `Harite Studio` のような印象先行の拡張命名は採用しない。

### 2. 上部帯

- 上部は標準的なアプリケーション構成として読めることを優先する。
- `Prefs` `Help` `About` は補助ボタン群ではなく、メニューバーとして置く。
- `Flow: Compose -> Optimize -> Apply` は維持する。
- `Save As` は flow から認識できる位置に置き、下方へ沈めない。

### 3. 中央 2 列目

- 上下左右の tgl ボタン系は、操作意味をボタン配置そのもので示す。
- `tglUpper*` / `tglLower*` は中央列センターへ置く。
- `tglPushLeft*` / `btnGetImg*` / `tglPushRight*` は [docs/specs/gui/gui-phase5-p5-7-xfce-validation-template.md](docs/specs/gui/gui-phase5-p5-7-xfce-validation-template.md) の `中央2列目イメージ` に沿ってセンタリングする。
- 左右ディスプレイイメージと十字配置が読めない左寄せ仮配置は採用しない。
- `Wallpaper Optimizer`、`Glade-like layout (Phase5 P5-2)`、`Compose / Input` のような中央列ラベルは不要である。

### 4. watch タブ

- タブ化の狙いは `Compose / Input` から `Apply` までの中央 2 列目エリアを watch 系統と入れ替えることにある。
- マージン類は watch タブとの入れ替え対象にしない。
- watch の設計は、main 側のレイアウトを壊さずに差し替える前提で考える。

### 5. 下部帯

- `Apply mode` など製作途中向けの情報表示は、ステータスエリアより下へ置く。
- debug 情報はアプリケーション最下部へ退避する。
- 本来的には不要寄りであり、将来は削除または隠す余地を残す。

### 6. 保留項目

- `Color` は今回の主レイアウト決定には含めない。
- ただし Color とのボタン配置だけは、開いたエリアへ用意する。
- 場所の再検討余地があるため、機能自体は保留とする。

## 相談ポイント

### 1. glade 再現の限界

- glade の xml から自明な配置要求を満たせない箇所があるなら、不可能と説明すること。
- その場合は、代替配置案と理由を必ず添えること。

### 2. 標準的なアプリケーションデザインとの整合

- `Secondary / Meta` のような独自カテゴリは癖が強く、標準的なアプリケーションデザインから外れやすい。
- 補助導線はメニューバー `Prefs` `Help` `About` として置く方がよい可能性が高い。

### 3. 主操作の未検証

- `Apply` 等の主要操作はまだ未検証であり、現時点では close 判定へ進めない。
- したがって、レイアウト再設計と主要操作検証を切り分けず、Phase6 継続事項として扱う。
