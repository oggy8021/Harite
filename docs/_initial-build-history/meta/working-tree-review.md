# ワーキングツリー中心のチャットレビュー運用（草案）

目的

- チャット内でドラフトをレビューし、最終合意が得られてから PR を作成するワークフローを標準化する。

概要フロー

1. ドラフト作成（チャットで本文を共有／編集）。
2. チャット内で合意を得る（本文を最終確認）。
3. ローカルでコミットを作成（`feature/` ブランチを main から派生）。
4. リモートへ push し、必要に応じてドラフト PR を作成（レビュー向け）。
5. CI を通した上で squash マージし、作業ブランチを削除。

運用ルール（要点）

- PR 作成は「最終合意時のみ」。合意前は PR を作らない。
- コンフリクト解消はローカルで行い、チャット内で合意してから push する。
- Web Editor 等でリモート上から直接コンフリクト解消しない。
- ブランチ命名: `feature/`、`fix/`、`docs/` 等のプレフィックスを使用。
- `save/*` はバックアップ扱いで PR チェックをスキップする運用を維持。

補足: 本草案はレビュー用です。運用手順やチェックリストの追記希望があれば指示ください。
